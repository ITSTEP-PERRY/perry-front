По закрытому чеклисту Figma-переписи:

| Показатель | Число |

## 3. Текущий объём кода (линия A)

Замер по рабочим папкам (`src/pages`, `widgets`, `app`, `styles`, `api`, `hooks`), без `node_modules`:

| Зона | Файлов | ≈ строк |
|------|-------:|--------:|
| Страницы (`src/pages`) | 28 | ~6 600 |
| Виджеты (`src/widgets`) | 19 | ~1 900 |
| App (Context + router) | 5 | ~400 |
| Стили CSS (`storefront` / `admin` / `auth`) | 3 | ~6 900 |
| API + hooks | 5 | ~900 |
| **Итого линия A** | **~60** | **~16 500** |

Задел линии B (`Components/`, `forms`, `theme`, DeepStyles): **~400 строк** — на 22 экрана почти не влияет.

**TypeScript переписывать не нужно** (уже в проекте).

---

## 4. Сколько строк нужно переписать

| Сценарий | Что делаем | Оценка объёма работ |
|----------|------------|---------------------|
| **A. Только Redux** | Context → RTK slices; UI/CSS как есть | **~1–3 тыс.** строк (store + правки потребителей) |
| **B. antd + Redux** (рабочий единый стек) | UI на antd, состояние на Redux; Figma 1:1 не гарантируем | **~10–15 тыс.** строк переписать/заменить (почти все pages/widgets + большая часть CSS) |
| **C. antd + Redux + пиксель-перфект Figma** | как B + жёсткая темизация / overrides | **~10–15 тыс.+** и дольше по сроку |

### Интерпретация

- Просьба «antd, redux и typescript» по факту = сценарий **B** (или **C**, если нельзя терять макет).
- Из ~16 500 строк линии A **большинство UI (~pages + widgets + CSS ≈ 15 000)** при полном переходе на antd **не переедет copy-paste** — их нужно заменить или сильно переписать.
- API-клиент (~900 строк) и значимая часть доменной логики **можно сохранить** и обернуть в Redux thunks/RTK Query.

## 5. Оценка сроков (ориентир)

Один сильный фронтенд, без параллельной защиты:

| Сценарий | Срок |
|----------|------|
| A. Только Redux | ~3–7 дней |
| B. antd + Redux без жёсткого Figma | ~1–2 недели |
| C. antd + Redux с сохранением макета | ~2–4+ недели |

Перед защитой сценарии B/C — **высокий риск**: только что закрыта перепись 22 экранов под Figma.

## 6. Куда это стыкуется с репозиториями

| Репо | Что по миграции |
|------|-----------------|
| **perry-front** | Основной удар: витрина → antd+Redux |
| **perry-admin-front** | У команды уже эталон antd+RTK; наша админка туда **по решению не пушится** |
| **Product / Back_end_…** | Менять не обязательно ради UI-стека; API остаётся |

Пуш «всей работы» в три репо **≠** автоматически миграция на antd. Это отдельное архитектурное решение.

---

## 7. Рекомендация

1. **До защиты:** оставить линию A (Figma-порт) как working витрину; TypeScript уже общий.  
2. **На созвоне команды:** зафиксировать source of truth (A сейчас / B после защиты).  
3. Если выбирают B — завести **отдельный этап** «миграция на antd+RTK» с оценкой **~10–15k LOC / ~22+ экранов**, не смешивать с текущими PR по пиксель-перфекту.  
4. Ответ в чат можно формулировать так: стек TS уже общий; полный переход на antd+Redux = перепись порядка **10–15 тысяч строк** и **всех ~22 экранов**, это недели, не «подключить библиотеки».
